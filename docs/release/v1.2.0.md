# TKAI Framework V1.2.0 General Availability Preparation

## Release status

V1.2.0 is prepared for general availability on the release branch. This
document records executed validation only; no Git tag, GitHub Release, or PyPI
publication has been created.

- Release date: 2026-07-23
- Baseline commit: `859ed29 chore(release): finalize licensing for GA`
- Version: `1.2.0`

## Included foundations

- Policy Engine and explicit policy pipeline.
- Retry policy, budgets, classification, and local backoff decisions.
- Failure-isolated EventBus and local Telemetry foundations.
- Local Distributed Backend, membership, cooperative heartbeat, and locks.
- Explicit Adaptive Routing and Multi-region routing foundations.
- Offline benchmark infrastructure, stress validation, and reliability
  validation.

## Compatibility

V1 public import paths, provider/configuration fields, CLI parameters, Doctor
fields, default behavior, and existing AIClient/ProviderManager behavior remain
compatible. V1.2 foundations are opt-in; they do not automatically take over
ProviderManager, Runtime, or AIClient calls.

## Quality and validation

- Full test suite: `327 passed` before the GA version update; the final gate is
  rerun for this commit.
- Eight local benchmark modules, 15 stress tests, and 11 reliability tests run
  offline with bounded workloads.
- Ruff, Black, Mypy, import smoke, CLI smoke, Doctor smoke, and public API
  compatibility checks are release gates.

## Packaging and fresh install

`python -m build` is unavailable locally, so the release validation used the
offline setuptools backend to create `tkai-1.2.0.tar.gz` and the local
no-dependency wheel path to create `tkai-1.2.0-py3-none-any.whl`. Both artifact
lists contain the `tkai` package, default template resources, README, and MIT
license data; neither contains caches, credentials, environment files, or local
paths. Wheel metadata confirms the package name, version `1.2.0`, MIT license,
license file, Python requirement, dependencies, and `tkai` entry point.

A temporary environment installs the local wheel with no network dependency
and checks `import tkai`, version output, CLI help, Doctor text/JSON, key public
imports, minimal configuration loading, and default template resources. The
temporary environment and artifacts are removed after validation.

## Known limitations

- Local-memory implementations only; no Redis backend or real distributed
  synchronization.
- No automatic failover, active health probing, traffic migration, ML routing,
  or OpenTelemetry SDK integration.
- No Git tag, GitHub Release, or PyPI publication is performed by this branch.

## Upgrade notes

Upgrade from V1.1 or a V1.2 release candidate by installing the V1.2.0 artifact
when approved. Existing APIs and default behavior remain compatible. The V1.2
foundations remain explicit opt-in integrations.

## Rollback notes

If release validation discovers a regression before publication, do not create
or move a tag. Retain the prior approved artifact and revert only the affected
release-preparation commit on a follow-up branch after review.

## Manual release steps

1. Push and merge the approved branch.
2. Build and inspect wheel and sdist in the target release environment.
3. Create annotated tag `v1.2.0` after approval.
4. Create the GitHub Release and publish artifacts only when separately
   authorized.
