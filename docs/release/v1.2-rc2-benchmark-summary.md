# TKAI V1.2 RC-2 Benchmark Summary

This is a structural release-validation manifest, not a cross-machine
performance comparison. It deliberately does not record elapsed time,
throughput, or latency values because those figures depend on the host,
interpreter, and current system load.

All suites are local-only, deterministic in scenario selection, and use the
shared `BenchmarkRunner` and `BenchmarkResult` model. Each command writes
Markdown by default and JSON when passed `--json`.

| Module | Default operations | Scenarios | Markdown | JSON |
|---|---:|---|---|---|
| Policy | 10 | allowed, rejected, default | Yes | Yes |
| Retry | 10 | retryable, non-retryable, budget limit, manager path | Yes | Yes |
| EventBus | 10 | zero/single/multiple subscribers, subscribe cycle, isolated failure | Yes | Yes |
| Telemetry | 10 | enabled/disabled metric, trace, structured log, summary | Yes | Yes |
| Distributed | 10 | local backend, local lock, membership snapshot | Yes | Yes |
| Adaptive Routing | 10 | signal recording, ranking, cold start | Yes | Yes |
| Multi-region | 10 | registration, ranking, selection, unavailable path | Yes | Yes |
| Combined Runtime | 5 | policy, region, adaptive, retry, local runtime stub, telemetry, EventBus | Yes | Yes |

The `BenchmarkResult` schema remains available for local inspection:
`operations`, `elapsed_seconds`, `ops_per_second`, `mean_latency_ms`,
`p50_latency_ms`, `p95_latency_ms`, `p99_latency_ms`, `min_latency_ms`, and
`max_latency_ms`. RC-2 does not publish the values or establish thresholds.

## Offline commands

```bash
python -m benchmarks.policy
python -m benchmarks.retry --json
python -m benchmarks.eventbus
python -m benchmarks.telemetry
python -m benchmarks.distributed
python -m benchmarks.adaptive_routing
python -m benchmarks.multiregion
python -m benchmarks.combined_runtime
```

None of these commands initializes a real provider or contacts a network
endpoint.
