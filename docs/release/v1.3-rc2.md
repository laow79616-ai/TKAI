# TKAI Framework V1.3 RC-2 performance and reliability validation

## Release status

Release-candidate validation in progress; this document records the RC-2 gate.

- Baseline commit: `ba14e2b8287710e741ee663be6b8d2b5cac3dd1b`
- Candidate version: `1.3.0rc1`
- RC-1 integration status: passed.

## Offline validation

The RC-2 suite adds repeatable, no-network validation for injected Redis backend
operations, health-cache reads, service registry operations, telemetry spans and
metrics, and explicit runtime-scheduler decisions. Every scenario uses the
existing nearest-rank benchmark infrastructure and produces stable Markdown or
JSON representations; it intentionally makes no machine-specific performance
claim.

Bounded stress tests cover fake-Redis operations, health probes, registry
registration/lookup/removal, telemetry records, and concurrent scheduler
decisions. Reliability tests cover offline Redis health failure and recovery,
local-memory failover, telemetry exporter isolation, scheduler no-candidate
behavior, and repeated lifecycle cleanup.

## CLI and Doctor

The supported compatibility commands are `tkai --help`, `tkai version show`,
`tkai doctor`, and `tkai doctor --json`. No root `--version` option is added.
All diagnostics remain local and do not require Redis to be installed.

## Known limitations

- Redis tests use an injected fake client only; no live Redis, cluster, or
  cross-process validation is claimed.
- Runtime scheduling remains explicit and does not take over `ProviderManager`.
- No active provider probing, traffic migration, or automatic provider failover
  is implemented.

## RC-3 recommendation

Proceed to RC-3 only after the full quality gate and repeated benchmark, stress,
and reliability suites pass in the target release environment.
