# TKAI V1.1 RC-1 release checklist

## Quality baseline

- [x] Full offline pytest suite passes.
- [x] Ruff, Black, Mypy, and `git diff --check` pass.
- [x] Stable and compatibility import paths have regression coverage.
- [x] Public snapshot and metadata JSON representations have regression
  coverage, including credential redaction.
- [x] All AI CLI subcommands have registration/help smoke coverage.
- [x] Doctor aggregation remains read-only, ordered, and failure-isolated.
- [x] Import smoke coverage confirms package modules do not require a network
  request, plugin loading, or provider initialization at import time.

## Release metadata

`tkai.__version__` and `pyproject.toml` currently agree on `1.0.0rc1`.
This RC-1 quality baseline intentionally does not change the formal version or
create a tag.  A release manager must select and update the final V1.1 version
in both canonical locations before publishing.

## Packaging

The package uses setuptools package discovery rooted at `src`, includes the
new subsystem packages, and declares runtime requirements in `pyproject.toml`.
The build command is run only when the local `build` module is already
available; no dependency is installed for release validation.

## Known limitations

- State is in-process memory only; there is no distributed synchronization.
- Redis cache/rate-limit backends are not supplied.
- No OpenTelemetry or Prometheus exporter is included.
- Health is passive; it does not probe providers.
- Routing, breakers, rate limiting, cache, load, and plugins are opt-in and do
  not automatically take over `ProviderManager`.
- There is no cross-region routing, adaptive/ML routing, or general retry
  framework beyond the provider transport scope.
- Plugins have no sandbox, remote loading, hot reload, dependency resolver, or
  marketplace.

## RC-2 decision gate

Proceed only after release ownership chooses the formal V1.1 version and a
separate release review confirms packaging artifacts in the intended publish
environment.  No RC-2 code scope is implied by this checklist.
