# TKAI V1.1 RC-2 performance and reliability baseline

## Scope and method

RC-2 uses dependency-free, offline microbenchmarks in `benchmarks/`.  The
shared runner reports operations per second, average/median/p95/p99/max
latency, CPU time, and wall time.  Timings are an engineering baseline, not a
cross-machine performance promise: they are affected by host scheduling and
the local Python interpreter.

The suite never makes a provider request or accesses the network.  It measures
the optional V1.1 services in isolation, so it does not change normal
`ProviderManager` execution.

## Environment

- Host: MacBook Pro, 4 CPU cores, 8 GB memory.
- OS: Darwin 24.6.0 x86_64.
- Python: 3.12.13.
- Date: 2026-07-23 (local offline run).

## Reliability validation

- Stress tests cover concurrent routing/plugin registration, cache reads and
  writes, quota consumption, EventBus dispatch, repeated subscription cleanup,
  and registry clearing.
- Soak tests execute 100,000 routing decisions, cache reads, EventBus publishes,
  and plugin dispatches without external I/O or uncaught errors.
- `EventBus` now serializes subscribe, unsubscribe, publish, and clear state
  transitions.  `RateLimitManager` serializes the local
  read/consume/update sequence, preventing concurrent quota-update loss.

## Known bottlenecks and limitations

- Sliding-window quota consumption is intentionally exact and scans local
  window entries; it is materially slower than fixed-window consumption at
  large local windows.
- Hook dispatch scales linearly with enabled plugins because stable priority
  ordering and failure isolation are retained.
- Event, cache, rate-limit, and plugin event histories are in-memory diagnostic
  lists.  Long-running applications should use their documented `clear()` or
  lifecycle cleanup boundaries; RC-2 does not introduce a retention policy.
- These are single-process, in-memory measurements.  They do not measure
  provider network latency, distributed synchronization, Redis backends,
  OpenTelemetry/Prometheus exporters, or cross-region routing.

## Reproduction

Run individual scripts from the repository root, for example:

```bash
python benchmarks/routing.py
python benchmarks/cache.py
python benchmarks/eventbus.py
python benchmarks/rate_limit.py
python benchmarks/plugin_hooks.py
python benchmarks/provider_runtime.py
```

Then run the reliability suite with `pytest tests/stress tests/soak -q`.

## Packaging validation

The RC-2 environment did not have the local `build` module installed, so
`python -m build` was intentionally skipped after recording the missing-module
result.  No network installation was attempted.  Source-tree CLI validation
completed successfully with `python -m tkai ai --help`; wheel and sdist
installation verification remains a release-environment gate.
