## Distribution rules

Release artifacts must contain the `tkai` package and metadata-required
documentation, but must not contain repositories, caches, credentials, local
environment files, benchmark output, or local absolute paths. Generated wheel,
sdist, and temporary virtual environments are validation artifacts only and are
not committed.

The initial RC-3 wheel audit found that `templates/default/template.json` and
the default template README were missing. The release-blocking packaging defect
was fixed with a minimal `tool.setuptools.package-data` declaration and the
rebuilt wheel includes both files.

## Known limitations

- The standard `build` module may be unavailable in an offline environment; an
  offline `pip wheel --no-deps` fallback is used where possible.
- RC-3 does not validate real provider traffic, distributed backends, active
  health probes, automatic failover, Redis, or OpenTelemetry.
- RC-3 does not create a GA tag or publish an artifact.

## GA recommendation

**Not Ready** until release ownership supplies a non-empty, approved `LICENSE`
file and corresponding project license metadata. The repository currently has
an empty `LICENSE` file, and no authoritative license choice is recorded in
version control. Choosing a license or copyright holder is a legal/release
ownership decision and is intentionally not inferred by this validation work.

After that decision, rerun the packaging, content, fresh-install, and quality
commands recorded below before creating any GA tag.

## Manual steps before GA

1. Add the approved license text and declare matching package metadata.
2. Run artifact build and inspect wheel and sdist contents in the target release
   environment.
3. Install the local wheel in a fresh environment, then repeat CLI and Doctor
   smoke checks.
4. Obtain release-owner approval, push the branch, and create a tag only after
   all release gates are green.
