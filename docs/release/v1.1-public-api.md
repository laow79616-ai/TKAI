# TKAI V1.1 RC-1 public API baseline

This document freezes the public surface verified by the V1.1 RC-1 quality
baseline.  It is an import and compatibility contract, not a promise that every
implementation detail is suitable for direct construction.  Objects not listed
here, or imported from a module whose name begins with an underscore, are
internal unless a prior compatibility document says otherwise.

## Stability levels

- **Stable** — supported public API for the V1.x line; preserve signatures,
  behaviour, and import paths or provide a compatibility shim.
- **Provisional** — public extension point whose API may gain additive fields
  in a later minor release; preserve existing callers.
- **Internal** — implementation detail; use only through the stable facade.

## Runtime and adapter APIs

The provider runtime is intentionally separated from the normal client facade.
It remains public for provider implementors, but is **Provisional**:

- `tkai.ai.runtime`: `ProviderRuntime`, `LifecycleState`, `OwnershipPolicy`,
  `RequestScope`, retry framework types.
- `tkai.ai.sync_bridge`: `SyncBridge`.
- `tkai.ai.openai_runtime_adapter`: `OpenAIProviderRuntimeAdapter`.
- `tkai.ai.transport_adapter`: `TransportAdapter`, `resolve_transport`, and
  transport type aliases.
- `tkai.ai.transport`: `HTTPResponse`, `raise_for_status`.
- `tkai.providers.http`: `AsyncHTTPTransport`, streaming parser/normalizer
  types.

Provider implementations must depend on these modules rather than private
`httpx` client ownership details.  The legacy callable transport path remains
supported through `TransportAdapter`.

## Compatibility import paths

The following historical paths remain supported and are deliberately covered
by the RC regression suite:

| Historical path | Compatibility role |
| --- | --- |
| `tkai.config` | Original settings/configuration facade; retained alongside optional `tkai.configuration`. |
| `tkai.template_engine` and `tkai.templates` | Existing template APIs and manager paths. |
| `tkai.plugins.Plugin` | Legacy `activate()` / `deactivate()` plugin protocol. |
| `tkai.commands.ai` | Existing `tkai ai list`, `models`, `chat`, and `embed` command adapters. |
| `tkai.workflow` | Workflow V1 facade retained independently of AI subsystems. |

## CLI contract

The `tkai` entry point and `tkai ai` group are Stable.  RC-1 verifies help and
registration for `doctor`, `health`, `observability`, `breaker`, `routing`,
`load`, `rate-limit`, `cache`, and `plugins`, plus the legacy `list`, `models`,
`chat`, and `embed` commands.  These commands remain thin presentation layers:
they do not load plugins, make provider requests, or perform network probes
merely by being imported or by rendering help.

## Explicit opt-in policy

Routing, breakers, rate limiting, cache, load collection, plugins, and
observability are independent optional services.  They do not automatically
take over `ProviderManager` or `AIClient` execution in V1.1.  Health collection
is passive and never performs a provider network probe.
