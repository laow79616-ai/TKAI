# TKAI V1.1 release candidate notes

## Release scope

V1.1 consolidates the provider-neutral AI framework and adds optional local
infrastructure for credentials, persistent configuration, passive health,
observability, circuit breaking, routing, load, rate limiting, cache, and the
Plugin SDK.  Each foundation is opt-in and remains independent of normal
`AIClient` and `ProviderManager` execution.

## Highlights

- Provider runtime with async transport support, synchronous compatibility
  bridge, injectable fake transports, normalized streaming, and safe lifecycle
  ownership.
- Provider registry, model/capability routing, ordered fallback policy, and
  offline Doctor diagnostics.
- Safe credential discovery and immutable persistent configuration resolution.
- Passive local health, observability events, circuit breaker, cost/load routing,
  rate-limit, cache, and plugin foundations.
- `tkai ai` read-only inspection commands for Doctor and optional foundations.
- Offline examples for basic provider use, multiple providers, cache, Plugin
  SDK hooks, and explicit custom routing.

## Backward compatibility

There are no intended breaking changes in this release candidate.

- Existing `AIClient`, `AIProvider`, `ProviderManager`, synchronous provider,
  streaming, configuration, and CLI interfaces remain available.
- Legacy plugin `activate()` / `deactivate()` lifecycle support remains intact.
- New service foundations do not automatically take over ProviderManager.
- Existing configuration formats and precedence remain supported.

The complete import contract is maintained in
[V1.1 public API baseline](v1.1-public-api.md).

## Upgrade guidance

Existing V1 users can upgrade without source changes.  To adopt a V1.1
foundation, explicitly construct and wire its manager in application code; do
not assume automatic provider execution changes.  For example, cache and
routing examples demonstrate explicit ownership under `examples/ai/`.

## Version audit

The canonical version sources agree:

- `pyproject.toml`: `1.0.0rc1`
- `tkai.__version__`: `1.0.0rc1`

This branch intentionally does not create a Git tag or alter the formal
version.  Release management must make any final V1.1 version decision in both
canonical locations before publishing.

## Packaging validation

The local setuptools PEP 517 backend generated and inspected both a wheel and
an sdist for `1.0.0rc1`.  Their metadata, RECORD, README, LICENSE, package
contents, and `tkai = tkai.cli:main` console entry point were present.  Both
artifacts were installed offline into fresh virtual environments with the
locally available runtime dependencies; `import tkai`, `pip check`, and AI CLI
text/JSON smoke commands succeeded.  The conventional `python -m build`
wrapper was unavailable locally, so it was not installed from the network.

## Known limitations

- State is single-process and in memory; no Redis or distributed synchronization
  is included.
- Health is passive; no provider probe is performed.
- There is no OpenTelemetry/Prometheus exporter, multi-region routing, adaptive
  routing, or default ProviderManager takeover.
- Plugins have no sandbox, remote loading, hot reload, dependency resolver, or
  marketplace.
- The local release environment may require a separately installed `build`
  module for the conventional `python -m build` command.
