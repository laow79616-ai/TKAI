# TKAI TikTok Cloud Control Platform V4.0

Version 4.0.0 is a local, single-user release. The primary Windows example path is
`C:\Users\laow7\Documents\TKAI`. It does not require live TikTok access for startup,
health checks, automated tests, backup, or restore.

## Quick start and installation

Open PowerShell, then:

```powershell
cd C:\Users\laow7\Documents\TKAI
Copy-Item configuration\local.example.json configuration\local.json
.\scripts\setup-tkai.ps1
npm --prefix dashboard/frontend run build
npm --prefix studio/frontend run build
.\scripts\start-tkai.ps1
```

The API, Dashboard, and AI Studio bind to `127.0.0.1` by default. LAN exposure is
not enabled by the local profile.

## Configuration

`configuration\local.json` is typed and validated. `TKAI_<FIELD_NAME>`
environment variables override scalar values, for example `TKAI_BACKEND_PORT`.
Ports must be distinct and in 1024-65535; runtime paths must remain under the
repository. Secret values are not accepted in the database URL. Keep real secrets
in the configured external secret provider.

Desktop-safe defaults limit browsers, tabs, workflow/publishing/collection/
interaction concurrency, queues, payload size, exports, and query rows. Raise
limits deliberately only after measuring local resource use.

## Start, stop, status, and health

Use `scripts\start-tkai.ps1`, `scripts\stop-tkai.ps1`,
`scripts\status-tkai.ps1`, and `scripts\health-tkai.ps1`. Start validates the
virtual environment, Node tooling, ports, configuration, and runtime directories.
Partial startup rolls back owned processes. Stop is idempotent and removes only
repository-scoped PID references after process ownership checks.

`/health` is the backend liveness summary. `/readiness` and
`/tiktok/system/health` report database/runtime/UI/module/route readiness without
contacting TikTok. `/local-runtime/status` is the Dashboard-safe runtime view.

## Backup and restore

Run `scripts\backup-tkai.ps1`. Backups include the SQLite database, sanitized
configuration, metadata, and SHA-256 manifest; private media is excluded by
default. Startup never deletes or silently replaces an existing database.

Stop TKAI before restore, then run `scripts\restore-tkai.ps1 -Backup <path>`.
Restore requires explicit confirmation, validates every manifest hash, and creates
a safety backup first. A corrupt, incompatible, locked, or unverified database
stops with a readable error.

## Upgrade and rollback

Before upgrading: stop services, create and verify a backup, record the current Git
commit, and build the release package. Apply migrations only after backup.
On failure, stop services, return to the recorded commit or prior package, restore
the verified backup, start, and verify readiness. Never delete `runtime\data`.

## Troubleshooting and diagnostics

Run `scripts\diagnose-tkai.ps1`. For a port conflict, stop the owning process or
select three unused loopback ports. Stale PID files are cleaned by bounded shutdown.
For SQLite locking, stop other TKAI processes and retry; do not replace the file.
Frontend blank pages usually mean a missing production build or a route/API error;
rebuild both frontends and inspect sanitized logs under `runtime\logs`.

## Security and local operations

Keep loopback binding, tenant/workspace scoping, RBAC, approvals, and encrypted
references enabled. Do not store cookies, sessions, tokens, proxy passwords, or
private media in logs, release archives, or source control. PID files are scoped to
this checkout and process termination verifies the command line before stopping.
Production-local mode must not expose debug endpoints or default credentials.

## Architecture and TikTok modules

The FastAPI composition root deterministically registers Account Center, Browser
Runtime, Proxy Center, Account Farming, Content Center, Publishing Center, Data
Collection Center, Interaction Center, Risk Control Center, Workflow Center,
Operations Center, Analytics Center, and Local Runtime. The central readiness
registry checks package presence and duplicate routes while avoiding live TikTok.
Dashboard and AI Studio consume the same loopback API.

## Release and checks

Build both frontends, then run `scripts\build-release.ps1` and
`scripts\validate-release.ps1`. The archive contains runtime/source, production UI
builds, templates, scripts, docs, migrations/deployment resources, version metadata,
and checksums. It excludes virtual environments, `node_modules`, runtime/user data,
databases, profiles, cookies, sessions, credentials, logs, backups, temporary files,
and private media. See `release-checklist.json` and `docs\tiktok\V4.0-Release-Checklist.md`.

## Known limitations

- Automated tests do not depend on live TikTok.
- There is no CAPTCHA bypass, restriction circumvention, security bypass, or
  anti-detection guarantee.
- Browser automation requires a locally configured supported runtime.
- Docker Compose CLI validation requires Docker to be installed.
- External proxy health depends on user configuration.
- The platform remains focused on local single-user operation.
